# Implementation Plans

Generated by the `improve` skill on 2026-07-22, against commit `cf1b0f5`.

## The one rule that governs all of these

The repository owner's stated priority, verbatim: *"what i care is the code is
clean and the website is perform well (with the same visual that i made without
any lag)."*

Every plan here is therefore bound by a hard constraint:

> **The site must look pixel-identical after the change. No layout shifts, no
> timing changes, no restyling.** If a change cannot be made without altering
> what the user sees, it does not belong in these plans — stop and report
> instead.

Converting `<img>` to `next/image` is **explicitly ruled out** in every plan.
It is the single largest available loading-speed win, and the owner declined it
because the hero and product cards use layered subject/background compositions
with hand-tuned CSS. The 81 `@next/next/no-img-element` lint warnings are
expected and deliberate — do not "fix" them.

## Dependency notes

- **001 must land first.** It is the verification baseline. `npm run lint`
  currently reports 14 errors and 85 warnings, so it always exits non-zero —
  which means it cannot tell anyone whether a later change broke something.
  Every other plan ends with "lint is clean" as its safety check, and that check
  is meaningless until 001 lands.
- **006 requires 004.** Both modify `getPromoTimestamp` in
  `src/components/home/promo-data.ts`. 004 fixes how the date is *computed*
  (timezone); 006 changes how it is *rendered* (translation). Running them in the
  other order loses the timezone fix.
- **002 and 003 are independent of each other** and can be done in either order
  once 001 is green.
- **007 should land last** so it documents the repository as it actually ends up,
  including the `typecheck` script from 001 and the `onPreloaderDone` helper from
  002.

## What each plan does, in plain terms

- **001** — Makes the automatic code checker pass. Right now it always reports
  errors, so it can't warn anyone when something genuinely breaks. Nothing about
  the site changes; this just restores the safety net.
- **002** — Fixes a real bug. Under certain timing (notably switching language
  while the intro animation is still finishing), everything below the hero can
  stay permanently invisible. The fix already exists in the codebase but was
  only applied to one of the four places that need it.
- **003** — Pure speed. Deletes background animation work the browser is doing
  for content that is scrolled off-screen or hidden, and fixes timers that never
  get cleaned up. Nothing looks different; there is simply less work happening.
- **004** — When the database is unreachable the site quietly falls back to
  sample content and says nothing, which makes problems impossible to diagnose.
  This adds logging. It also fixes promo end-dates, which are currently computed
  in the server's timezone rather than Jakarta's.
- **005** — Two security fixes: a crafted login link can currently bounce a
  visitor to an external site, and the site sends none of the standard
  protective response headers.
- **006** — A few promo and search labels are hardcoded Indonesian and stay
  Indonesian on the English and Chinese versions of the site.
- **007** — The README is still the default template and is actively wrong;
  there is no `.env.example`, so a fresh clone cannot be configured.

## Findings considered and rejected

Recorded so nobody re-audits them.

- **Convert 84 `<img>` to `next/image`** — the largest loading-speed win
  available, declined by the owner because of the layout risk to hand-tuned
  layered image compositions. Revisit only with screenshot-based verification and
  an explicit go-ahead.
- **Split the 61 KB search corpus out of the initial bundle** — genuine loading
  win, but the search dropdown could briefly render empty on first focus, which
  is a visual change the owner ruled out. Revisit only if load time becomes a
  measured problem *and* a prefetch strategy can guarantee the dropdown is never
  empty.
- **`target="_blank"` without `rel="noopener"`** — not a finding. All 24
  occurrences already carry `rel="noopener noreferrer"`.
- **Supabase anon key exposed to the browser** — not a finding. It is a
  `NEXT_PUBLIC_*` key by design, and RLS is correctly enabled with select-only
  `anon` policies (`supabase/product-section.sql:56-66`,
  `promo-section.sql:47-59`, `news-section.sql:56-66`).
- **XSS sinks** — none. Zero `dangerouslySetInnerHTML`, `innerHTML`, `eval` or
  `new Function` anywhere in `src/`.
- **Secrets committed to git** — none. `.env*` is gitignored, nothing is tracked,
  nothing appears in history.
- **Translation key drift** — none. `messages/{id,en,zh}.json` have exactly 171
  keys each, zero missing, zero extra.
- **Carousel autoplay restarting on every render** — already handled
  deliberately; `ProductSection.tsx:1117-1119` memoises the ref array with a
  comment explaining precisely this hazard.
- **Search re-ranks on every keystroke without debouncing** — 147 records inside
  a `useMemo`. Measured cost is negligible; debouncing would add latency for no
  gain.
- **"Dead rung" in the `products.ts` Supabase fallback ladder** — reported by an
  audit pass, but incorrect. Attempt 3 is reachable when attempt 2 fails on the
  *category* columns while product translation columns exist. A smaller real gap
  remains (no `CAT_BASE + PROD_NO_I18N` rung, so one migration combination drops
  `is_featured` unnecessarily); too low-value to plan.
- **Forcing dynamic rendering so promo countdowns are never stale** — rejected.
  It would trade away static/ISR rendering for the whole homepage to make badge
  text at most 5 minutes fresher.
- **Constant-time comparison of the preview password** (`src/proxy.ts:28`) —
  rejected. Network jitter dwarfs the timing signal on a shared preview gate.
- **Dependency upgrades** — nothing to do. Five runtime dependencies, all on
  current majors (Next 16.2.10, React 19.2.4).

## Known follow-ups, deliberately not planned

Not bugs, but decisions someone should make before this site goes live:

- The auth cookie stores the shared preview password verbatim
  (`login/page.tsx:15`) rather than a derived token. Changing it logs out every
  existing preview session, so it needs a deliberate moment.
- The HaloBCA chat's reCAPTCHA falls back to Google's public always-pass test
  key when `NEXT_PUBLIC_RECAPTCHA_SITE_KEY` is unset, and no token is verified
  server-side because no chat backend exists yet (`HaloBcaChat.tsx:11-12,352`).
  Harmless today; a pre-launch checklist item.
- `LayoutSwitcher` / `useLayoutVariant` is self-described "Prototype-only"
  demo scaffolding that ships to production unless someone strips it
  (`src/lib/useLayoutVariant.ts:7-9`).
- The preview gate silently disappears when `PREVIEW_PASSWORD` is unset
  (`src/proxy.ts:26`) — safe by accident rather than by design.
- Nothing on the page is measured: searches, promo clicks and category switches
  emit no analytics, so the 147-record search corpus is being tuned blind.
- The search corpus is Indonesian-only, so English and Chinese queries often
  return nothing even after plan 006.
