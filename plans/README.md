# Implementation Plans

Plans **001–007** were generated by the `improve` skill on 2026-07-22 against
commit `cf1b0f5`. Plans **008–015** were added on 2026-07-27 against commit
`be4de7d`.

## The one rule that governs all of these

The repository owner's stated priority, verbatim: *"what i care is the code is
clean and the website is perform well (with the same visual that i made without
any lag)."*

Every plan here is therefore bound by a hard constraint:

> **The site must look pixel-identical after the change. No layout shifts, no
> timing changes, no restyling.** If a change cannot be made without altering
> what the user sees, it does not belong in these plans — stop and report
> instead.

Converting `<img>` to `next/image` is **explicitly ruled out** in every plan.
It is the single largest available loading-speed win, and the owner declined it
because the hero and product cards use layered subject/background compositions
with hand-tuned CSS. The ~77 `@next/next/no-img-element` lint warnings are
expected and deliberate — do not "fix" them.

**`archive/` is never touched by any plan.** It holds reference snapshots
(`PercentGlass.tsx`, `SoliprioSection.tsx`, `ProductSection.tsx`, and
`lokasi-bca/`), is excluded from `tsconfig.json` and ESLint, and is imported by
nothing. It is also the safety net that makes plan 012's deletions reversible.

## Dependency notes

Dependencies below are derived from **file overlap**, which is stricter than
logical dependency — two plans editing the same file must run sequentially or
their diffs conflict. Batch 1 learned this the hard way; batch 2 records it up
front.

- **010 requires 009.** Both edit `HeroWidget.tsx` and `MobileHeroWidget.tsx`.
- **012 requires 008 and 011.** 008 and 012 both edit `package.json`; 011 and
  012 both edit `src/app/globals.css`. Branch 012 from whichever lands last.
- **014 requires 013.** Both concern `MobileNav.tsx` — 013 renames its root to
  `<nav>`. (014 is written so it does not *modify* `MobileNav.tsx`, but it
  must be read against 013's version.)
- **008, 009, 011, 013 and 015 are mutually independent** and can run
  concurrently from `be4de7d`.
- **015 is fully disjoint** from everything else in both batches — it touches
  only `layout.tsx`, two new metadata routes, `tentang-bca/page.tsx` and
  `.env.example`. Run it whenever.
- **007 overlaps 015** on `.env.example`. Whichever runs second must *extend*
  the file rather than replace it.

A safe fully-sequential order: **008 → 009 → 010 → 011 → 012 → 013 → 014 → 015**.

Executors work in throwaway git worktrees under `.claude/worktrees/` on
branches named `advisor/NNN-*`. **Nothing is merged to `main` — merging is the
owner's decision.**

## What each batch-2 plan does, in plain terms

- **008** — The installed Next.js version has 9 known high-severity security
  advisories. One of them describes a bypass of exactly the kind of
  password-gate this site uses to stay private. Fixed by a patch upgrade.
- **009** — The search box, the most-used control on the page, is invisible to
  screen readers: it has no name at all. Two lines of code.
- **010** — Several panels are hidden by making them transparent, which hides
  them from the eye but not the keyboard. Tab currently lands on invisible
  buttons and invisible login links.
- **011** — 198 animations run continuously from the moment the page loads, for
  confetti that sits far below the fold. This parks them while off screen.
  Nothing looks different; there is simply less work happening.
- **012** — The map feature was removed but left behind a 44 MB dependency,
  ~200 lines of dead CSS, a 133 KB data file, and a security policy still
  granting access to a map-tile server the site no longer contacts.
- **013** — Screen-reader users have no way to jump to the navigation, no
  indication of which page they are on, and no way to skip past the navbar.
- **014** — The mobile menu behaves like a dialog but is not marked as one:
  Escape does not close it and keyboard focus escapes to the hidden page
  behind it.
- **015** — With one environment variable unset, this preview site advertises
  the real bank's domain in its share cards. Also adds the standard
  hreflang/sitemap/robots that a three-language site should publish.

## Findings considered and rejected

Recorded so nobody re-audits them.

### From the 2026-07-27 pass

- **`globals.css` architecture** — audited for the first time; it is healthy.
  All 51 defined classes were cross-referenced against usage, and **every**
  unused one is Lokasi BCA fallout (covered by plan 012). No accumulated dead
  rules, no specificity wars.
- **`prefers-reduced-motion` coverage** — mature, not a finding. 14 CSS blocks
  plus real JS checks in `SmoothScroll.tsx:39`, `Preloader.tsx:182`,
  `ScrollReveal.tsx:38` and `PromoSection.tsx:310`.
- **Carousel autoplay / WCAG 2.2.2** — satisfied. `EventSlider` and
  `HeroSection` both expose real pause controls (`onTogglePause`).
- **Passive event listeners** — already universal. No scroll/touch/wheel
  listener lacks `passive`.
- **`will-change` overuse** — only 6 usages, all scoped and deliberate. Left
  alone; removing the confetti's would change rasterisation (see plan 011).
- **Lazy-loading the remaining `<img>`s** — 46 of 82 lack `loading`/`decoding`
  attributes, but nearly all are above-the-fold hero and navbar chrome where
  lazy loading would *hurt* LCP. The ones in hidden panels would pop in
  visibly when opened. Not worth doing.
- **Soliprio border beam not parked** — investigated and **false**. It is
  already parked: `animation-play-state: paused` by default, flipped by an
  IntersectionObserver in `SoliprioCard.tsx:64-75` and by the active-slide
  check in `SoliprioMobile.tsx:213`.
- **`scrollToLocation` is dead after the map removal** — investigated and
  **false**. Both `Navbar.tsx:274` and `MobileNav.tsx:30` were already rewired
  to open the real BCA locator in a new tab. The function name is now
  misleading, but the behaviour is correct; a rename is not worth a plan.
- **`src/proxy.ts:42-44`'s `/api/` branch** — dead now that the three
  `/api/locations/*` routes are deleted, but harmless, defensive and correct
  for any future route handler. Deliberately left in place.
- **`scripts/fetch-bca-locations.mjs`** — orphaned by the map removal but
  deliberately kept. It is the documented way to regenerate the dataset if the
  feature ever returns, and it never ships to the browser.
- **Search dropdown ARIA combobox semantics** — the results are real `<a>`
  elements in `<ul>/<li>` and are already keyboard reachable. Full
  `combobox`/`listbox` semantics with arrow-key navigation is an enhancement,
  not a fix, and carries interaction risk on a tuned surface.
- **`useAutoplayProgress` ignores `prefers-reduced-motion`** — real, but
  changing it alters behaviour the owner tuned, and visible pause controls
  already satisfy WCAG 2.2.2. Needs the owner's sign-off, not a plan.
- **Major dependency upgrades** (`eslint` 9→10, `typescript` 5→7,
  `@types/node` 20→26) — real blast radius, no forcing function. Deliberately
  excluded from plan 008, which is a patch bump only.

### From the 2026-07-22 pass

- **Convert 84 `<img>` to `next/image`** — declined by the owner because of
  layout risk to hand-tuned layered image compositions. Revisit only with
  screenshot-based verification and an explicit go-ahead.
- **Split the 61 KB search corpus out of the initial bundle** — genuine loading
  win, but the search dropdown could briefly render empty on first focus, which
  is a visual change the owner ruled out.
- **`target="_blank"` without `rel="noopener"`** — not a finding. All
  occurrences already carry `rel="noopener noreferrer"`.
- **Supabase anon key exposed to the browser** — not a finding. It is a
  `NEXT_PUBLIC_*` key by design, and RLS is correctly enabled with select-only
  `anon` policies.
- **XSS sinks** — none. Zero `dangerouslySetInnerHTML`, `innerHTML`, `eval` or
  `new Function` anywhere in `src/`.
- **Secrets committed to git** — none. `.env*` is gitignored, nothing tracked.
- **Translation key drift** — none. Re-verified 2026-07-27 at 271/271/271.
- **Carousel autoplay restarting on every render** — already handled
  deliberately, with a comment explaining the hazard.
- **Search re-ranks on every keystroke without debouncing** — negligible
  measured cost inside a `useMemo`; debouncing would add latency for no gain.
- **"Dead rung" in the `products.ts` Supabase fallback ladder** — reported by
  an audit pass, but incorrect.
- **Forcing dynamic rendering so promo countdowns are never stale** — would
  trade static/ISR rendering for the whole homepage to make badge text at most
  5 minutes fresher.
- **Constant-time comparison of the preview password** (`src/proxy.ts:28`) —
  network jitter dwarfs the timing signal on a shared preview gate.

## Known follow-ups, deliberately not planned

Decisions someone should make before this site goes live:

- **`/tentang-bca` is an empty shell** that the navbar links to with a
  view-transition treatment. A visitor clicking "Tentang BCA" lands on a blank
  blue page. Plan 015 marks it `noindex` and keeps it out of the sitemap, but
  it still needs either real content or a hidden link before launch.
- The auth cookie stores the shared preview password verbatim
  (`login/page.tsx:15`) rather than a derived token. Changing it logs out every
  existing preview session, so it needs a deliberate moment.
- The HaloBCA chat's reCAPTCHA falls back to Google's public always-pass test
  key when `NEXT_PUBLIC_RECAPTCHA_SITE_KEY` is unset, and no token is verified
  server-side because no chat backend exists yet.
- `LayoutSwitcher` / `useLayoutVariant` is self-described "Prototype-only" demo
  scaffolding that ships to production unless someone strips it. It is still
  rendered — see `PromoSection.tsx:397`.
- The preview gate silently disappears when `PREVIEW_PASSWORD` is unset
  (`src/proxy.ts:26`) — safe by accident rather than by design.
- Nothing on the page is measured: searches, promo clicks and category switches
  emit no analytics, so the 147-record search corpus is being tuned blind.
- The search corpus is Indonesian-only, so English and Chinese queries often
  return nothing even after plan 006.
