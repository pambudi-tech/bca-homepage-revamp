## Why this matters

`npm audit` reports **9 high-severity advisories** against the pinned
`next@16.2.10`, plus transitive high-severity advisories in `postcss` and
`sharp`. The one that matters most here is *"Middleware / Proxy bypass in App
Router applications using Turbopack and single locale"*.

That advisory describes exactly this app's architecture. `src/proxy.ts` is a
Next.js proxy that implements the **preview password gate** — the only thing
keeping this unreleased site private — and it wraps `next-intl`'s locale
middleware. A proxy bypass defeats that gate entirely. Two further advisories
(Server Action DoS, Server Action SSRF) are also reachable: `src/app/[locale]/login/page.tsx`
submits through a Server Action.

The fix is a **patch bump within the same minor**: 16.2.10 → 16.2.12.

## Steps

### Step 1: Bump both pinned Next versions

In `package.json`, change exactly two values:

- `dependencies.next`: `"16.2.10"` → `"16.2.12"`
- `devDependencies.eslint-config-next`: `"16.2.10"` → `"16.2.12"`

Keep them identical to each other and keep the exact-pin style (no `^`).
Change nothing else in the file.

**Verify**: `grep -n '"next"\|"eslint-config-next"' package.json`
→ both lines read `16.2.12`.

### Step 2: Install and confirm the advisories are cleared

Run `npm install`.

**Verify**: `npm audit --omit=dev` → the summary line reports
`found 0 vulnerabilities`, or at minimum **0 high**. If any high-severity
advisory remains, record which package and go to STOP conditions.

### Step 3: Confirm the static gates still pass

Run, in order:

1. `npm run typecheck` → exit 0, no errors.
2. `npm run lint` → exit 0.

**Expected lint baseline**: `78 problems (0 errors, 78 warnings)`. The
warnings are **deliberate and must not be "fixed"**: 76 `@next/next/no-img-element` (deliberate; the owner
declined `next/image`), 1 `react-hooks/exhaustive-deps` in
`src/lib/useLayoutVariant.ts:29`, and 1 `@typescript-eslint/no-unused-vars`
for `PRODUCT_VARIANTS` at `src/components/home/ProductSection.tsx:16`.

A different warning **count** is acceptable if the upgrade changed how the
Next ESLint plugin reports. A single new **error** is a STOP condition.

### Step 4: Confirm the production build succeeds

Run `npm run build`.

**Verify**: exit 0. The build must complete and emit routes for `/[locale]`,
`/[locale]/login` and `/[locale]/tentang-bca`.

Read the build output for any new deprecation warning naming a Next API. If
one appears, note it verbatim in your report — do not act on it in this plan.

### Step 5: Confirm the preview gate still works

This is the whole point of the upgrade, so verify the gate end to end rather
than assuming it survived.

`src/proxy.ts` only arms the gate when `PREVIEW_PASSWORD` is set. Start the
production server with a throwaway value:

```bash
PREVIEW_PASSWORD=plan008check npm run start
```

Then, in a second shell:

1. `curl -s -o /dev/null -w '%{http_code} %{redirect_url}\n' http://localhost:3000/`
   → expect a **307** redirect whose target path is `/login`.
2. `curl -s -o /dev/null -w '%{http_code}\n' -H 'Cookie: preview_auth=plan008check' http://localhost:3000/id`
   → expect **200**.

The cookie name `preview_auth` comes from `src/lib/preview-auth.ts`, whose
entire contents are:

```ts
export const AUTH_COOKIE_NAME = "preview_auth";
```

The gate compares the cookie value against `PREVIEW_PASSWORD` verbatim
(`src/proxy.ts:27-28`), which is why the throwaway password above doubles as
the cookie value.

Stop the server when done.

**Verify**: unauthenticated request redirects to `/login`; the request
carrying the correct cookie returns 200. If an unauthenticated request returns
200 for any path other than `/opengraph-bcacoid.png`, that is a gate bypass —
STOP immediately and report.
